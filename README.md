# CS-300
This is for the Module 8 Assignment Submission
In this course, the primary problem I was solving was how to efficiently store, manage, search, and display course data from a CSV file for the Computer Science program. The system needed to load course information, allow users to search for specific courses by course number, display prerequisites, and print all courses in alphanumeric order. This required selecting and implementing appropriate data structures that could handle insertion, searching, and sorted output efficiently. 

To approach this problem, I first focused on understanding the strengths and weaknesses of different data structures, including vectors, hash tables, and binary search trees. Data structures are important because they directly affect a program’s performance, scalability, and maintainability. For example, while a vector is simple to implement, searching can be inefficient without sorting. Hash tables provide fast lookups but do not naturally maintain sorted orders. The binary search tree offered a strong balance by allowing efficient insertion and searching while also maintaining data in sorted order through in-order traversal. Based on runtime and memory analysis, I determined that a binary search tree was the best fit for this application. 

During development, I encountered roadblocks related to organizing the logic for inserting nodes correctly, handling edge cases such as duplicate or missing data, and ensuring the tree maintained proper structure. Breaking the problem into smaller pieces helped significantly improve. I first wrote clear pseudocode outlining each function’s responsibilities, such as Insert, Search, Remove, and InOrder traversal. Testing each function individually before integrating them into the full menu-driven program allowed me to isolate and fix errors more efficiently. Analyzing time complexity also helped me better understand where performance issues might occur. 

Working on these projects expanded my approach to software design by reinforcing the importance of planning before coding. Writing pseudocode first made my final implementation cleaner and more structured. I also developed a deeper understanding of how algorithmic complexity impacts real-world performance. Instead of focusing only on making the program work, I now consider efficiency, scalability, and future adaptability from the start. 

Finally, this project evolved the way I write programs by emphasizing readability and maintainability. I learned to separate responsibilities into clear functions, use meaningful variable names, and design modular components that can be updated or expanded without rewriting the entire system. Structuring the menu logic, data loading, and tree operations separately made the program easier to debug and understand. Overall, this experience strengthened both my technical understanding of data structures and my ability to design well-organized, efficient software systems
